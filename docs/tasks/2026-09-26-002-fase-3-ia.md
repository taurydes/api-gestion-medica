## Defectos encontrados y corregidos

| Defecto | Efecto | Corrección |
|---|---|---|
| `create` no acotaba por médico | Un médico podía registrar análisis sobre archivos de citas ajenas (IDOR de escritura) | `assertAppointmentAccess` → 403 |
| `create` devolvía la entidad cruda (con `rawResponse`, `imagePath`) y el resto de endpoints la serializada | Forma distinta según endpoint | `create` devuelve `serialize()` |
| `numeric` salía como string en `GET /:id` | `probability: "47.27"` | Transformer numérico |
| El detector filtra por content type | Una subida del navegador como `application/octet-stream` daba 415 | Tipo por firma de bytes |
| POST y GET con distinta precisión | El front vería 96.188… y luego 96.19 | Redondeo antes de guardar |

## Decisiones

| Decisión | Motivo |
|---|---|
| 400 en vez de descartar los campos del modelo | El `ValidationPipe` global corre antes que uno de parámetro y ya habría quitado los campos con `whitelist`; se declaran con `@IsEmpty` (mensaje explícito) |
| `highRisk` = `status = 'danger'` (revisado 2026-09-27; antes `malignancyProbability ≥ 80`) | El criterio M-40 del plan es "highRisk = número de filas MALIGNANT". El modelo decide MALIGNANT con malignidad ≥ 85 (`rawScore ≤ 0,15`): con el corte en 80 un BENIGN de malignidad 80–85 contaba como alto riesgo y la UI se contradecía. `minProbability` sigue filtrando por malignidad (filtro del usuario) |
| `minProbability=80` puede devolver un benigno con malignidad 80–85 | Es la semántica correcta; el criterio del plan ("ningún BENIGN") se cumple con los datos actuales (máx. benigno 64,40) |
| Datos: fórmula sobre la columna `probability` (2 decimales) | Instrucción del plan; error ≤ 5e-5 en `raw_score`, dentro de la tolerancia 1e-4 |
| `down()` del backfill limpia solo filas sin `model_version` | Las filas del detector siempre lo traen (`sha256:…`) |
| Detector con respuesta 200 incoherente → 503 | Nunca persistir un resultado inventado |
| Preview limitado a 20 MB también para DICOM | Coherente con el detector; un DICOM mayor se convierte antes con `/files/dicom-convert` |
| DICOM analizado se guarda como el JPEG enviado al detector | `imageUrl` sirve algo visible y permite re-inferir |
| Sin endpoint para guardar un análisis sin archivo de cita | El contrato solo acepta `appointmentFileId`; el detector independiente usa preview |
